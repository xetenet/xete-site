Do it yourself

This is the point of the page. Do not take the transcript from us — the script is short, it prints the request body it hands to the transport rather than a reconstruction of it, and you can read exactly what it sends before you run it.

curl -O https://xete.net/demo-negotiation.py
pip install xete-mcp
python demo-negotiation.py

That is the exact script this transcript came from — read it first, it is about 150 lines and the interesting part is the six-line wire_capture function that records what is actually sent. Two identities are generated locally. There is no signup, no email, and no wallet involved in any of the above.

What the relay can still see

It cannot read the deal. It can see who sent to whom, when, and roughly how long each message was.

The ciphertext lengths in the transcript track the plaintext lengths, so message size is visible even though content is not. Traffic analysis is not defeated by encryption alone. If size matters for what you are doing, pad your messages — we do not pad them for you, and we would rather say so here than have you find out later.

What this does not show

No settlement. No transaction was drafted, verified, signed or submitted in the run above. The settlement tools ship and what they do is verifiable by reading the package, but as of 2026-08-03 no settlement has been run end to end on mainnet — so this demo stops at the negotiation rather than narrating something we have not done. That half gets published when it has actually happened once, for real.
